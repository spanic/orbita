# Orbita Market — описание и план развития проекта

## Цель проекта

- Разработать ядро платформы **Orbita Market**, предназначенной для оформления заказов на приобретение спутниковых снимков (архивных, отложенных или периодических) с оплатой в геокредитах.

- Вывести ядро платформы в демонстрационную эксплуатацию, провести сквозное тестирование и презентовать результаты стейкхолдерам.

## Стейкхолдеры

| Роль                       | Интересы                                                                                                                                                             |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Оператор ДЗЗ**           | Заказать различные типы снимков с необходимыми параметрами, отслеживать статус заказа и получать информацию об ошибках и причинах их возникновения                   |
| **Аналитическая компания** | Получить спутниковые снимки для анализа и использования в различных целях и проектах, создать счет на платформе и при необходимости пополнять его для оплаты заказов |
| **Product owner**          | Получать статистику по заказам и использованию платформы и на их основе принимать решения о её развитии                                                              |

## План развития

> Сроки выполнения работы: с 16.06.2026 по 12.07.2026

### Этап №1 — Разработка сервиса для оформления заказов (_orders service_)

1) Первичный анализ требований, выбор технологического стека, определение основных компонентов, их ролей и способа их взаимодействия
2) Создание репозитория для проекта, настройка локального окружения и инструментов разработки
3) Создание шаблона архитектуры проекта, проверка работоспособности инструментов сборки и unit-тестирования
4) Разработка базового функционала сервиса: создание заказов, получение списка заказов для текущего пользователя, получение информации о заказе
5) Unit-тестирование разработанного функционала, тестирование API

#### Результаты этапа
- Создан репозиторий для проекта, настроены и проверены инструменты разработки, тестирования и сборки
- Базовый функционал сервиса для оформления заказов разработан и протестирован

### Этап №7 — Подготовка к разработке фронтенда

1) Документирование API-контрактов: формирование актуальной OpenAPI-спецификации для всех эндпоинтов сервисов, описание форматов запросов и ответов
2) Реализация аутентификации на уровне бэкенда: выдача и валидация JWT-токенов, эндпоинты регистрации и входа в сервисе payments, передача идентификатора пользователя в downstream-сервисы через заголовки
3) Настройка CORS и проверки JWT на уровне API-gateway для поддержки браузерных клиентов
4) Выбор технологического стека фронтенда (фреймворк, сборщик, инструменты линтинга и форматирования), создание скаффолда проекта
5) Проектирование пользовательских сценариев и разработка UI-макетов для ключевых экранов: создание заказа, список заказов, аккаунт и баланс
6) Определение структуры компонентов, стейт-менеджмента и слоя взаимодействия с API

#### Результаты этапа
- Аутентификация реализована на уровне бэкенда, эндпоинты регистрации и входа работают и возвращают JWT
- OpenAPI-спецификация актуализирована, API-gateway настроен для работы с браузерными клиентами
- Технологический стек выбран, шаблон проекта создан, инструменты разработки настроены и проверены
- UI-макеты для ключевых пользовательских сценариев согласованы, архитектура фронтенд-приложения определена

#### Сроки выполнения
13.07.2026 – 15.07.2026 (3 дня)

5) Интеграция с бэкенд-сервисами через API-gateway, обработка ошибок и граничных состояний
6) Компонентное и интеграционное тестирование фронтенда, устранение найденных ошибок

#### Результаты этапа
- Пользовательский интерфейс платформы реализован и протестирован
- Все ключевые сценарии (управление аккаунтом, оформление и отслеживание заказов) доступны через веб-приложение

16.07.2026 – 25.07.2026 (10 дней)

### Этап №9 — Развёртывание платформы

1) Выбор облачной инфраструктуры, подготовка продакшн-окружения: сервер, сеть, группы безопасности
2) Настройка CI/CD-пайплайна: автоматическая сборка Docker-образов и публикация в реестр по событию пуша в основную ветку
3) Настройка продакшн-конфигурации сервисов: переменные окружения, секреты, параметры подключения к БД и брокеру сообщений
4) Настройка домена, выпуск и привязка TLS-сертификата, конфигурация Nginx для HTTPS-терминации
5) Развёртывание всех сервисов платформы в продакшн-окружении, дымовое тестирование (smoke testing) сквозных сценариев
6) Настройка базового мониторинга и логирования: сбор метрик доступности сервисов, централизованный сбор логов

#### Результаты этапа
- Платформа развёрнута в облачной инфраструктуре и доступна по публичному HTTPS-адресу
- CI/CD-пайплайн настроен и проверен, выкладка новых версий автоматизирована
- Базовый мониторинг доступности и логирование настроены, платформа готова к демонстрации стейкхолдерам
